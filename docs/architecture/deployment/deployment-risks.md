# Deployment and operational risks

Скилл: `deployment-topology-analyzer` (+ Mermaid).
Область: текущая поставка и локальный запуск решения; production-развёртывания
в репозитории нет. Источник фактов — `runtime-evidence.md`.

## 1. Реестр рисков

| ID | Риск | Влияние | Доказательство | Серьёзность |
| --- | --- | --- | --- | --- |
| R1 | Нет воспроизводимого артефакта развёртывания: ни образа, ни CI, ни IaC | Live-демо зависит от ручной настройки машины; до 25 баллов за работоспособность | отсутствие `Dockerfile`/CI/IaC; `AGENTS.md` §9; `docs/…/hackathon-evaluation.md:45-55` | **высокая** |
| R2 | Жёсткая зависимость активной конфигурации от двух платных/внешних API | Без сети или валидных ключей пайплайн не выдаёт результат; 401 уже наблюдался | `config.json:2-3`; `jev/client.py:93-95`; `sample_llm/client.py:35-36`; `README.md:85-88` | **высокая** |
| R3 | Свежий клон не содержит `out/`-артефактов, нужных 5 модулям | Альтернативные классификаторы падают при инициализации | `out/` в `.gitignore`; `tfidf/pipeline.py:22-27`; `model.py:185-203`; `jev_retrieval/pipeline.py:31-35` | средняя |
| R4 | Секреты только в `.env`; менеджера секретов нет | Утечка при копировании/демонстрации; ротация вручную | `.env.example`; `.gitignore:1-5`; `main.py:301` | средняя |

| R12 | Нет владельца runtime и on-call | Неясно, кто чинит ключи/окружение на демо | в репозитории владелец не назначен | низкая |

## 2. Что подтверждено как устойчивое

- Выбор модулей валидируется строго: неизвестный ключ или отсутствующий модуль —
  явная ошибка без тихого переключения (`main.py:233-271`).
- Выход LLM валидируется Pydantic-схемой, ответы Jev проверяются по составу
  вопросов и диапазону вероятностей (`jev/client.py:32-49`,
  `sample_llm/pipeline.py:14-21,45-50`).
- Отсутствие ключа/артефакта обнаруживается до платного вызова
  (`jev/client.py:93-94`, `tfidf/pipeline.py:22-27`).
- Запись выходов и кэшей атомарная (`main.py:213-220`, `jev/client.py:51-64`).
- Версии зависимостей зафиксированы `uv.lock`; код не имеет побочных эффектов
  на импорте (`main.py:318-321`).

## 3. Недостающие доказательства и следующие проверки

| Что неизвестно | Почему важно | Проверка |
| --- | --- | --- |
| Хостинг, кластер, регион, аккаунт | Топология за пределами рабочей машины не подтверждена | `find` по IaC/CI (см. `runtime-evidence.md` §8); вопрос команде |
| Как именно проходит live-демо | Влияет на R1 и R13 | уточнить у организаторов формат: CLI или HTTP |
| Актуальность ключей BestAPI/Google | Блокирует R2 | `uv run python src/main.py …` на тестовом входе; ожидать явную ошибку, не пустой ответ |
| Наличие `out/`-артефактов на демо-машине | Блокирует R3 | `ls -d out/tfidf.json out/hybrid-training.jsonl out/semantic-encoder` |
| Сетевая политика площадки | Может блокировать egress | `curl -sS -o /dev/null -w '%{http_code}' https://bestapi.fugue.pro/` |
| Время и стоимость активной конфигурации | Требуется на защите | прогнать `full_pipeline_evaluation --live` и заполнить README вручную |

## 4. Рекомендации (по приоритету)

1. **R1/R13:** добавить минимальный `Dockerfile` и команду запуска
   (`docker run -v $PWD/data:/app/data …`), либо явно зафиксировать в README,
   что демо — CLI на ноутбуке. Контейнер убирает зависимость от локального Python.
2. **R2:** подготовить офлайн-деградацию: `tfidf` или `semantic_encoder`
   как fallback-классификатор и шаблонный генератор без API; заранее собрать
   `out/`-артефакты и проверить ключи до демо.
3. **R3:** приложить к релизу `out/tfidf.json` и `out/semantic-encoder/`
   (или команду их сборки в Dockerfile), иначе альтернативы неработоспособны
   на чистой машине.
4. **R6:** выровнять политику повторов: retry с backoff для Jev и structured LLM
   на 429/5xx/таймаут, как у генератора.
5. **R5/R4:** зафиксировать, какие поля описания отправляются наружу; не логировать
   ключи; для демо использовать отдельный `.env` с ограниченной квотой.
6. **R7:** на защиту предоставить измеренные среднее/медиану/p95 и стоимость
   из существующих бенчмарков; автоматический расчёт цены не требуется.
7. **R9-R11:** привести `pyproject.toml`/`AGENTS.md` к одной версии Python,
   объявить `scipy` явно, описать CPU-профиль обучения.

## 5. Ограничения анализа

- Нет runtime-наблюдений (подов, инстансов, логов, метрик, трейсов), поэтому
  диаграммы отражают **конфигурацию и код**, а не фактический продакшен.
- Владелец сервиса и площадка демонстрации в репозитории не зафиксированы.
- Внешние endpoint'ы взяты из значений по умолчанию в коде и `.env.example`;
  фактический DNS/сеть площадки не проверялись.
