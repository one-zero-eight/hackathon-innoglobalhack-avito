# HTTP API полного пайплайна

```bash
uv sync
uv run python -m src
```

Сервер: http://127.0.0.1:8000. Swagger: [/docs](http://127.0.0.1:8000/docs),
OpenAPI: [/openapi.json](http://127.0.0.1:8000/openapi.json).
Host/port задаются через `UVICORN_HOST` и `UVICORN_PORT` в окружении или `.env`.
Запускается один процесс, inference выполняется последовательно — это локальная demo-версия.
Файловый CLI `src/main.py --input ... --output ...` также доступен.

Генератор `local_llm` общий с CLI и React-бэкендом `api.app:app`
(`POST /api/drafts`); оба читают `config.json.draft_generation`. Это разные
HTTP-приложения: `python -m src` не обслуживает React `/api/*`.
Модуль универсального API — `src/http_api.py`, фабрика — `http_api:create_app`;
пакет `src/api/` предназначен только для веб-бэкенда.
Локальный runtime Qwen3.5-9B и его веса устанавливаются и запускаются отдельно,
не при `uv sync` и не через Compose. Инструкции — в разделе
[«Веб-сервис»](../README.md#веб-сервис).
Для CLI/dev endpoint по умолчанию `http://127.0.0.1:8080/v1/chat/completions`,
для контейнера — `http://host.docker.internal:8080/v1/chat/completions`.
MLX alias: `LOCAL_LLM_MODEL_ID=default_model`; таймаут `LOCAL_LLM_TIMEOUT=180`,
лимит `LOCAL_LLM_MAX_TOKENS=4096`. Endpoint меняется через `LOCAL_LLM_API_URL`.
Текст содержит вступление и списки `•`; исходные эмодзи выбираются вторым
запросом без переписывания слов. Автоматических повторов генерации нет.

## Выбор модулей

`GET /modules` возвращает `extractors`, `generators` и `defaults.extractor/generator`.
Оба списка строятся одинаково: папки модулей с `pipeline.py` и `__init__.py`,
прошедшие существующую проверку имени. Импорт и конструкторы моделей не вызываются.
Среди генераторов доступны `local_llm` (по умолчанию) и `sample_llm`.

В `POST /drafts` Swagger показывает оба списка как dropdown. Эквивалентный HTTP-вызов:

```bash
curl -X POST 'http://127.0.0.1:8000/drafts?extractor=lexical.regex&generator=local_llm' \
  -H 'Content-Type: application/json' \
  -d '{"description":"Устанавливаю розетки и смесители.","mcId":101}'
```

Query-параметры необязательны. Отсутствующий `extractor` берётся из
`config.json.subcategory_extraction`, `generator` — из `config.json.draft_generation`.
Выбор действует только на этот запрос; файл конфигурации и defaults не меняются.
Пустая строка или неизвестное имя вызывают `422`; запасная модель автоматически не выбирается.

Тело запроса остаётся `{"description":"...","mcId":101}`.
Успешный ответ — `{"drafts":[{"mcId":104,"title":"...","text":"..."}]}`.
Список пуст, когда дополнительных услуг нет: `{"drafts":[]}`.
Служебные параметры, usage и selector-значения в результат не добавляются.

Добавление модуля с существующим интерфейсом автоматически добавляет его в каталог
и Swagger после перезапуска сервера. Новые registry-списки в коде не нужны.
Варианты весов, промпты и провайдеры остаются настройками `.env`; селектор выбирает модуль.
Ключи доступа и произвольные пути не принимаются через HTTP.

## Загрузка и ошибки

`config.json` и `.env` читаются относительно проекта при создании приложения.
Имена defaults проверяются при старте, но веса и клиенты загружаются лениво.
Наличие модуля в каталоге не означает наличие его весов, зависимостей, подготовленного
индекса или ключа провайдера. Неподготовленный модуль не мешает пользоваться остальными.
Для путей ресурсов в `.env` предпочтительны абсолютные пути, особенно при запуске из другого cwd.

Один `PipelineRuntime` хранит активный extractor и generator. Неизменённый шаг
переиспользуется; при смене selector ссылка на прежний экземпляр этого шага удаляется.
Первый запрос к модулю включает его загрузку, последующие — нет. Внутренние кэши самих
модулей продолжают работать по их правилам; API не гарантирует освобождение их глобальных ресурсов.
Замок охватывает выбор, загрузку и оба шага, поэтому параллельные запросы не смешивают
mutable state моделей. При пустых целях generator не загружается и не вызывается.

Runtime проверяет допустимость и уникальность target-категорий, исключает исходную
категорию и допускает не более одного draft на подтверждённую цель. Генератор может
отказаться от неподтверждённых услуг: допустимы подмножество целей и пустой список.
Дубли и категории вне списка целей по-прежнему отклоняются.

| HTTP | Причина |
| --- | --- |
| 200 | Подтверждённые черновики, включая корректный пустой список |
| 422 | Неверное тело, mcId или selector |
| 503 | Недоступны ресурсы/зависимости/настройки выбранного модуля либо API-ключ |
| 502 | Ошибка провайдера или некорректный результат модели |
| 500 | Непредвиденная программная ошибка |

Ошибки возвращают `detail` с безопасным сообщением; текст provider body, ключи и
traceback в HTTP-ответ не попадают. Учёт usage изолирован по запросам и не добавляется в контракт.
После изменения `.env`, defaults, весов или списка модулей сервер нужно перезапустить.

`GET /health` возвращает `{"status":"ok"}` без загрузки моделей и проверки облачных API.
Список модулей и документация также не вызывают inference.

## Проверка без API-расходов

```bash
uv run python src/draft_generation/benchmarks/full_pipeline_evaluation/run.py --api-check
uv run python src/draft_generation/benchmarks/sample_llm/run.py
```

Первая команда не требует PostgreSQL. Она проверяет селекторы, reuse, сериализацию,
валидацию и ошибки через TestClient, затем запускает реальный сервер на временном
локальном порту, проверяет HTTP и останавливает процесс. Платный транспорт заблокирован,
позитивная генерация использует контрольный ответ. Настоящий локальный regex проверяется
без облака. Результаты находятся в существующих сценариях, в их общих таблицах.
