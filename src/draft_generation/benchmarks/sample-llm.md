Сервис: draft_generation

## Что проверяем и почему

Минимальный генератор должен передать категорию и исходное описание
в LLM, принять только валидный JSON с непустыми title/text и добавить
правильный mcId независимо от модели.

Контрольный вход:

```json
{
  "input": {"description": "Устанавливаю розетки и смесители.", "mcId": 101},
  "target_mc_ids": [104, 104, 105],
  "llm_response": {"title": "Монтаж", "text": "Установка смесителей."}
}
```

Запуск:

```bash
PYTHONPATH=src uv run python -m draft_generation.benchmarks.replay_sample_llm
```

Проверка использует подмену транспорта/ответа модели в отдельном процессе.
Сетевых запросов нет. Контрольный ответ не оценивается на релевантность
категории: проверяется только программный контракт, не качество генерации.

## Выводы

Повторный прогон 2026-11-14 после перехода генератора исключительно на
`LLM_API_KEY`: все проверки прошли. Дополнительно проверено, что заголовок
Authorization содержит именно общий ключ, а `SAMPLE_LLM_API_KEY`
игнорируется и не заменяет отсутствующий `LLM_API_KEY`.

Эти результаты относятся к первоначальному клиенту Chat Completions.
Актуальный Google-клиент и реальный запуск описаны отдельно в
`gemini-generation.md`.
