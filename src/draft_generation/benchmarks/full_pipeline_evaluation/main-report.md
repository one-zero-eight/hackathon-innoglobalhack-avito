## Что проверяем

Реальный `tfidf → sample_llm` на всех 208 строках официального
`docs/innoglobalhack_avito/public-test-dataset.parquet`.
Источник mcId — 101, как задано `run.config.json`; в Parquet этого поля нет.
Модель, промпт и порог зафиксированы до оценки.
Метрика — sklearn micro-F1 по шести категориям; баллы классификации — 60 × F1.
Имена категорий проверяются по контракту. Повторы не увеличивают TP,
ошибочный вывод исходной категории даёт FP; пустые эталон и ответ дают F1=0.

Реальные черновики валидируются штатным `run_pipeline()`; кэш модели не используется.
Сохраняется каждая успешная строка. При сетевых ошибках повторяется настоящий
вызов, максимум 3 попытки с интервалом 60 с поверх штатных повторов клиента.
При исчерпании попыток прогон неуспешен; итоговый F1 не рассчитывается.

## Запуск

```bash
# Только офлайн-проверка формулы, чтения Parquet и пересечения с train
uv run python src/draft_generation/benchmarks/full_pipeline_evaluation/run.py

# Все строки и настоящая генерация
uv run python src/draft_generation/benchmarks/full_pipeline_evaluation/run.py --live --config run.config.json

# Продолжить после сетевого сбоя, сохранив уже измеренные ответы
uv run python src/draft_generation/benchmarks/full_pipeline_evaluation/run.py --live --config run.config.json --resume
```

Без `--resume` начинается новый прогон. Продолжение проверяет отпечаток данных,
конфигурации, кода, модели, промптов и весов. Оно не считается новым инференсом
уже готовых строк и сохраняет их исходное время.

Отчёты рядом: [офлайн](checks-results.json), [полный прогон](live-results.json).
Конфигурация модулей читается из `pipeline_config`; `limit: null` — все 208 строк.
Поле `report` из старого оценщика не управляет контрольной точкой этого бенчмарка.

## Как измеряется время

Таймер оборачивает настоящий `run_pipeline()` целиком: загрузку модулей и весов,
выделение категорий, генерацию всех черновиков и проверки контракта.
Ожидание квоты, сетевые ошибки и все повторы входят. Чтение датасета и запись
отчёта не входят во время строки. Число черновиков на строку различается;
пустые цели не вызывают генератор, поэтому важна отдельная статистика
пустых и непустых ответов. Экспертная достоверность текста не оценивается.

В [бенчмарке генератора](../response_time/README.md) каждый вход всегда
даёт ровно один настоящий запрос; это другая единица измерения.
