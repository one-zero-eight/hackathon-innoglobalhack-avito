# Проверки интерактивного разбора датасета (история)

Сервис: dataset_annotation  
Дата: 2026-11-14   Автор: ARCshekin

Историческая служебная проверка CLI. Она не описывает результаты новой политики полной разметки и не является оценкой реализаций классификатора.

## Что проверяем и почему

Проверяем CLI `review_dataset`: выбор номера, свой массив, ошибки ввода,
сохранение, продолжение и защиту предыдущих решений. Служебная проверка не
добавляет ответов в настоящий датасет: изменения пишутся только во временную
копию `decisions.json` внутри `src/dataset_annotation/work/`.

```json
{
  "options": [[102, 106], [106], []],
  "valid_answers": ["1", "2", "3", "[106,102]", " [] ", " [102, 106] ", "q", "выход", "s", "?"],
  "invalid_answers": ["", "0", "4", "102", "-1", "1.0", "{}", "null", "[101]", "[107]", "[\"102\"]", "[true]", "[102.0]", "[102,102]", "102,106", "[102,]"],
  "temporary_decision_example": {
    "split": "train",
    "source_row": 47,
    "answer": "[106]"
  }
}
```

Запуск:

```sh
PYTHONPATH=src uv run python -m dataset_annotation.check_review_cli
```

Для работы с реальными решениями:

```sh
PYTHONPATH=src uv run python -m dataset_annotation.review_dataset
```

`--preview` показывает первый случай без записи и пересборки.
`--split train|test|all` выбирает часть, `--limit N` ограничивает число
подтверждённых ответов. `s` пропускает случай в текущей сессии,
`q` завершает работу, `?` показывает справку. EOF/Ctrl+C не создают
неподтверждённого ответа.

версиях кода не запускалась. Перед коммитом действуют требования AGENTS.md.

Проверено:

- Корректный номер преобразуется в показанный набор.
- Массив проверяется строго: только целые 102–106 без дубликатов.
  101, bool, строки, дробные числа, объекты и некорректный JSON отклоняются.
- Повторное объявление одной группы не попадает в очередь.
- Предыдущее решение группы заменяется с сохранением истории.
- Устаревший снимок файла не может перезаписать новое решение.
- Временный файл записи убирается после атомарной замены.
- Цикл `invalid → help → quit` не сохраняет нового ответа.
- Цикл с массивом `[106]` сохраняет ответ в копию, вызывает пересборку
  и соблюдает `--limit 1`.
- Уже отвеченная группа исключается при повторном сборе очереди.
- Содержимое настоящего `decisions.json` после служебной проверки не меняется.
- Отдельно выполнен preview: первый следующий случай — train:47.

## Выводы

CLI продолжает после четырёх сохранённых ответов пользователя в чате.
Каждый ответ фиксируется немедленно и применяется к копиям только своего
описания и своей части данных; выбор для одного SEO-списка не обобщается.
После ответа пересобирается датасет с прежними проверками контракта
и происхождения. Необработанная неопределённость не исправляется автоматически.

Номера вариантов зависят от текущего случая; произвольный набор всегда
можно задать явно массивом.
