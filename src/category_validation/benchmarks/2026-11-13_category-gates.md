# Бенчмарк: фильтрация категорий и маршрутизация разногласий

Сервис: category_validation  
Автор: fih  
Дата: 2026-11-13

Сравниваем поиск упоминаний услуг, проверку предложения услуги и вызов модели
только при разногласии локальных методов. Целевая метрика — micro-F1 по
множествам дополнительных mcId. Исходная категория исключается из предсказаний.

## Методы

- **Regex** — общий способ искать слова и фразы по регулярным выражениям.
  **SplitShift regex** — конкретный набор правил из `splitshift/detector.py`.
  Он возвращает кандидатов по упоминаниям. В этом эксперименте названия
  `regex` и «SplitShift regex» обозначают один и тот же детектор. Старые
  идентификаторы приводятся к текущей таблице.
- **SplitShift regex + split gate** — логистическая регрессия на TF-IDF и
  признаках объявления принимает одно бинарное решение на всё объявление.
  Если она разрешает разбиение, проходят все кандидаты regex.
- **TF-IDF + gated regex** — отдельные модели оценивают категории по всему
  тексту. Категория получает прибавку к оценке, когда её находит regex и
  split gate разрешает разбиение объявления.
- **Decision 1 как арбитр** — один запрос на объявление, вопросы только
  о категориях, по которым два локальных метода расходятся. Сохраняем
  вероятности и сравниваем простой порог с порогами уверенности.
- **Планируемая проверка по категориям** — одна L2-логистическая регрессия
  для пар «объявление, категория». Сравниваем признаки всего объявления
  с теми же признаками плюс контекст около совпадений regex. Проверяем
  все пять возможных категорий, включая категории без совпадений.

## Данные и протокол

Новые прогоны используем только на InnoGlobalHack. Обучение и подбор порогов
проводим на групповых разбиениях `public-train-annotated.jsonl`. Близкие
описания держим вместе. Наивное разбиение строк дало 1 129 совпадающих
описаний на 2 000 строк проверки. Простой поиск точных совпадений дал
0.7256 micro-F1. Проверяем пересечение с `public-test-dataset.parquet`
и используем его после фиксации параметров.

Контрольные методы — пустой список, все пять дополнительных категорий,
SplitShift regex без фильтра. Считаем micro-F1, TP/FP/FN по категориям,
ложные срабатывания на объявлениях без целевых категорий и полноту
кандидатов regex. Для API записываем число запросов и входных токенов.
Лимит — 45 000 входных токенов за скользящие 60 секунд.
