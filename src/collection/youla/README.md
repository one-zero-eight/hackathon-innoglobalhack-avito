# Сбор описаний с Юлы

Из корня репозитория:

```sh
mkdir -p out
docker run --rm --init --shm-size=512m \
  -e MIN_LENGTH=300 -e TARGET_ROWS=100 \
  -v "$PWD/src/collection/youla:/collector:ro" -v "$PWD/out:/output" \
  mcr.microsoft.com/playwright:v1.56.1-noble bash -lc \
  'cd /tmp && npm install --no-audit --no-fund playwright@1.56.1 >&2 && NODE_PATH=/tmp/node_modules node /collector/collect-youla.cjs "$@"' \
  -- /output/youla-300.jsonl moskva kazan sankt-peterburg saratov
```

Запуск дописывает новые записи в JSONL. Повторный запуск с тем же файлом
пропускает сохранённые ID и совпадающие нормализованные описания. Три воркера используют общую очередь и набор просмотренных ID.
В строках файла с суффиксом `.cache` сохраняются прочитанные описания любой
длины до фильтрации по отзывам и категории. Телефоны и email маскируются. Чтобы применить другой порог без повторной загрузки карточек, передайте
путь к этому файлу через `SEED_FILES` и выберите новый файл для результата.
Сбор останавливается при явной проверке доступа или HTTP 403/429.

Берём текст из поля «Описание». Убираем хвосты с явно обозначенными отзывами
и поисковыми фразами. Порог по умолчанию — 750 символов. В команде выше задан минимум 300. Поле
`sample_mc_id` — предварительное соответствие вида услуг Юлы категории
кейса. Небольшой корпус для просмотра примеров.

Для серверного запуска с целью 5000 записей можно использовать
`bash src/collection/youla/run-youla-5000.sh` из корня репозитория.
Скрипт сохраняет прогресс в `out/youla-5000.jsonl` и повторяет успешные проходы
через 30 минут до достижения цели. Если проход завершается с ошибкой, скрипт
останавливается. Серверный режим просматривает до 60 карточек на вид услуги
и прокручивает каталог до 20 раз. Эти параметры задаются через
`MAX_VISITS` и `MAX_SCROLLS`. Для каждой прокрутки журнал показывает число новых ID,
общее число найденных ID и число ещё не просмотренных объявлений.
После двух прокруток без новых ID сбор переходит к следующему поиску.

## Следующие улучшения сборщика

- Добавлять новые ID в общую очередь по мере появления каждой порции
  результатов. Воркеры смогут загружать карточки, пока прокрутка
  каталога продолжается. Перед постановкой в очередь проверять ID по
  кэшу и уже поставленным в очередь объявлениям.
- Сохранять между проходами ID карточек с временными ошибками, число
  попыток и время следующей попытки. Увеличивать паузу при повторных
  сбоях и удалять запись об ошибке после успешной загрузки.
