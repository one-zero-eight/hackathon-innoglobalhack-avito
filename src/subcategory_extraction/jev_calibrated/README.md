# Jev: промпт и train-калиброванные пороги

Вариант `subcategory_extraction/jev_calibrated` сохраняет интерфейс
`run(PipelineInput) -> list[int]`. Нативный API-клиент и проверка вероятностей
используются из `jev`; контракт объявления и генератор не меняются.

## Выбор решения

Используются только метки `docs/innoglobalhack_avito/public-train-annotated.jsonl`.
Точные нормализованные дубликаты объединяются; близкие тексты группируются
char-TF-IDF/cosine с границей 0.85. Группы, содержащие описания любого из двух
test-наборов, исключаются по текстам, без использования test-меток.
Выборка фиксируется seed=20261115: 48 fitting-групп и 24 отдельные control-группы.
Из каждой группы берётся один представитель. Это небольшой пилот;
группировка эвристическая и не гарантирует нахождение всех перефразировок.

На fitting сравниваются `guided` и минимальный `baseline` и по девять схем
порогов: 0.5, общий порог, порог каждой категории и shrinkage к 0.5.
Критерий — pooled micro-F1 трёх group-crossfit folds; подбор каждого fold
не использует его метки. Все варианты порогов используют одни вероятности,
дополнительных API-вызовов для поиска порогов нет. Победитель по fitting
фиксируется до чтения контрольных результатов.

Control сравнивает выбранный вариант с `guided@0.5`. Артефакт сохраняется
только при улучшении control micro-F1 хотя бы на 0.002. Другой промпт или
порог по control не выбирается. Test-наборы используются после фиксации
для существующих регрессионных сравнений; они уже ранее просматривались
и не являются новым, никогда не виденным независимым holdout.

## Обучение и загрузка

```bash
uv run python src/subcategory_extraction/jev_calibrated/train.py --fit-size 48 --control-size 24
```

Это реальные запросы к настроенному Jev API. В текущем эксперименте модель
закреплена: Selectel `typesafe/jev-1.13`. `jev-latest` другого провайдера не
считается эквивалентной версией. Повтор команды использует проверенный кэш
по endpoint/model/payload. Неполный запуск не создаёт новую калибровку.
Отчёт — в существующем `benchmarks/classifier_methods/jev-training-results.json`.

Готовая калибровка хранится и коммитится вместе с вариантом:
`artifacts/calibration.json`. Loader проверяет провайдера, endpoint, точный
model, набор и диапазон порогов, хеш промпта. Все пути по умолчанию относятся
к файлу модуля. Порог категории 101 не обучается и остаётся 0.5, потому что
в train исходная категория всегда 101.

Для явной проверки без артефакта: `JEV_CALIBRATED_PROMPT=guided` или `baseline`.
`auto` — значение по умолчанию; требует готовый артефакт.
`JEV_CALIBRATION_PATH` задаёт другой файл. Калибровка не переносится между
моделями или провайдерами. В auto используются сохранённые пороги;
`JEV_THRESHOLD` применяется только к явному некалиброванному варианту.

## Существующие бенчмарки

Итог: выбранный на train вариант дал micro-F1 0.844376 на официальных 208
и 0.775068 на 119 диагностических строках (база 0.842415/0.816754).
Пилотный прирост control0.926829→0.939759 не стал общим улучшением обоих test.
Поэтому config.json сохраняет прежний jev; новый вариант остаётся явным
экспериментом. Параметры после test не подбирались и не переключались на
другой порог ради лучшей test-цифры. Для включения задайте
`subcategory_extraction: "jev_calibrated"` в config.json.

Дополнительное применение зафиксированных train-порогов guided к сохранённым
вероятностям дало 0.846847/0.800000. Это офлайн-абляция, не новый API-прогон;
guided не стал победителем crossfit и не показал прироста на control.

```bash
uv run python src/subcategory_extraction/benchmarks/classifier_methods/run.py --methods jev_calibrated --workers 1 --append
uv run python src/subcategory_extraction/benchmarks/improved_dataset/run.py --methods jev_calibrated --workers 1 --append
uv run python src/subcategory_extraction/benchmarks/response_time/run.py --module jev_calibrated --size 10 --append
```

Качество, пределы малого control и исходные даты публикуются в таблицах этих
сценариев после завершения. Стоимость записывается вручную в cpu_costs;
отдельного runner стоимости нет. Секреты остаются в `.env`.

Свежий latency-прогон нового варианта остановлен бюджетной проверкой до
первого вызова; нового значения latency нет. Предыдущие времена Jev не
подставляются вместо него.
