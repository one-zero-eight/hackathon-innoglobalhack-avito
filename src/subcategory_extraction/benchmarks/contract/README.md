## Что проверяем

Проверяем публичный loader и `run()` с подменой только ответа API. Сценарий
содержит 49 проверок: все шесть исходных категорий, исключение исходной,
один запрос на остальные категории, порядок результатов, граница порога,
пустые описания, подмножества вопросов, оба промпта, некорректные настройки,
оболочки, типы ответов и вероятности. Отдельно проверяем общие метрики:
официальные 60 × micro-F1, известные TP/FP/FN, пустые метки и пустой датасет.
Контрольный текст: «Устанавливаю раковины и меняю смесители.».
Ответы и неверные значения заданы непосредственно в `run.py`.

Это проверки интерфейса, а не оценка качества модели. Промпты формируют
вопросы, но модель на них не отвечает; лучший системный промпт не выбирается.
Ни F1 модели, ни время её ответа здесь не измеряются.

## Запуск

```bash
uv run python src/subcategory_extraction/benchmarks/contract/run.py --all-revisions
```

Без `--all-revisions` проверяется только рабочая копия. `--report` задаёт путь
к отчёту; по умолчанию используется [results.json](results.json).
Сравнение охватывает HEAD и все версии из истории `src/main.py` и
`src/subcategory_extraction/google_decision`. Старый код экспортируется через
`git archive` во временную папку и проверяется тем же сценарием в отдельном
процессе. Checkout пользователя не переключается. Отсутствующий модуль или
несовместимый старый `PipelineConfig` помечаются unavailable.

Случаи с порогом задают и старое, и новое имя переменной окружения, поэтому
сравнение не штрафует старый код за переименование настройки.
