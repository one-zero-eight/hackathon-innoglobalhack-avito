# Семантический encoder: дообучение RuBERT-tiny2

Сервис: `subcategory_extraction`  
Модуль: `semantic_encoder`  
Дата: 2026-11-14

## Метод и контракт

`SubcategoryExtractionPipeline(BasePipeline)` создаётся без аргументов;
`run(PipelineInput) -> list[int]` возвращает дополнительные микрокатегории
из общей таблицы `main.MICROCATEGORIES`, исключая исходную `mcId`.
Пример входа (не отдельная оценочная выборка):

```json
{"description": "Укладываю плитку, устанавливаю розетки и выключатели", "mcId": 101}
```

Используется реальный `AutoModel` **cointegrated/rubert-tiny2**, фиксированная
ревизия `e8ed3b0c8bbf4fb6984c3de043bf7d2f4e5969ae` (MIT).
Обучаются **все веса transformer и новая линейная multilabel-голова**, а не
логистическая регрессия поверх замороженных embeddings. Выходы головы идут
строго в порядке `MICROCATEGORIES`; sigmoid и единый порог **0.5** дают
независимые решения по категориям. На инференсе исходная категория исключается.

## Фиксированный эксперимент

Обучающий файл — `out/hybrid-training.jsonl`: 4821 уникальная строка официального
train после общего удаления точных/близких train-компонент, пересекающихся с
официальным test. Этот скрипт использует файл целиком, не пересчитывает исключения,
не читает test и сохраняет фактические число строк и SHA-256 файла в артефакте.
Метки — `found_microcategories`; исходная категория официального train всегда 101.

Настройки зафиксированы до итоговой оценки:

| Параметр | Значение |
| --- | --- |
| Эпохи | 3, все обучающие документы в каждой эпохе |
| Seed | 42, Python/PyTorch и отдельный generator перемешивания |
| Оптимизатор | AdamW, learning rate `3e-5`, weight decay `0.01` |
| Batch | 16 документов; последний batch не отбрасывается |
| Loss | обычный `BCEWithLogitsLoss`, без весов классов |
| Выходы | все шесть категорий из `MICROCATEGORIES` |
| Порог | 0.5, без калибровки |
| Validation / holdout | отсутствуют |
| Выбор checkpoint | последняя, третья эпоха; без early stopping |

Категория **101 не имеет положительных train-примеров**: её выход получает только
отрицательные метки. Это явно отражают `trained_classes`, `unsupported_classes` и
`positive_counts`, а также свойства пайплайна. При другой исходной категории
положительные 101 не подменяются чужими данными или эвристикой: используется
реальный выход головы. Поэтому перенос на предложения ремонта под ключ при
исходной категории, отличной от 101, ограничен составом официального train.
Фиксированный seed не означает побитовую идентичность CPU и MPS.

## Длинные тексты и общая архитектура

Нормализация: Unicode NFKC и свёртка пробельных последовательностей; регистр и
`ё` сохраняются. После токенизации всего текста без усечения выбираются не более
трёх окон по 512 токенов **вместе со служебными токенами**. Для доступной длины
содержимого `capacity` и `last = max(0, n_tokens - capacity)` начала окон:
`sorted({0, last // 2, last})`. Совпадающие позиции удаляются. Короткому документу
соответствует одно окно; у длинного остаются начало, середина и конец, а не только
первые 512 токенов. Между тремя окнами очень длинного текста возможны пропуски.
Перекрывающиеся токены участвуют в каждом выбранном окне.

В batch объединяются только **реальные** окна с индексами документов, без
фиктивных окон/документов для выравнивания их количества. Padding делается до
длины самого длинного реального окна batch. `attention_mask` исключает padding
из среднего; служебные токены включены. Суммы token embeddings и числа непустых
токенов объединяются по окнам документа, затем применяется линейная голова.
Все операции pooling сохраняют градиенты encoder; scatter/index-add не нужны.
Обучение и inference используют одну реализацию из `semantic_encoder/model.py`.

## Запуск и артефакт

Из корня репозитория:

```bash
PYTHONPATH=src uv run python -m subcategory_extraction.benchmarks.train_semantic_encoder --dataset out/hybrid-training.jsonl --device auto
```

`--device auto` выбирает MPS при `torch.backends.mps.is_available()`, иначе CPU.
Доступны явные `--device cpu` и `--device mps`; недоступный запрошенный MPS — ошибка,
не скрытый переход на CPU. При первой тренировке Hugging Face загружает именно
зафиксированную ревизию с `use_safetensors=True`. Ошибки загрузки/обучения не
заменяются фиктивной моделью. Зависимости: PyTorch, Transformers, safetensors.

`--artifact` меняет каталог сохранения, по умолчанию `out/semantic-encoder`:

- `encoder/`: дообученный `AutoModel.save_pretrained(safe_serialization=True)`;
- `tokenizer/`: `tokenizer.save_pretrained`, включая быстрый tokenizer;
- `head.safetensors`: реальные веса и bias линейной головы, без pickle;
- `metadata.json`: модель/ревизия, порядок классов, порог, нормализация, окна,
  настройки обучения, train SHA-256/число строк, положительные счётчики,
  поддержанные/неподдержанные классы, фактическое train-устройство и версии библиотек;
- `train-report.json`: та же конфигурация, реальные train BCE и время каждой эпохи,
  количество обучаемых параметров encoder/головы и общее время выполнения.

Для обычного запуска выбирается `subcategory_extraction: "semantic_encoder"` в
общем конфиге. Переменные окружения inference:

| Переменная | По умолчанию |
| --- | --- |
| `SEMANTIC_ENCODER_ARTIFACT_PATH` | `out/semantic-encoder` относительно корня репозитория |
| `SEMANTIC_ENCODER_DEVICE` | `auto` (`auto`, `cpu`, `mps`) |

Inference читает **только локальный** артефакт через `local_files_only=True`;
импорт модуля ничего не скачивает и не обучает. Несовместимый/отсутствующий артефакт
вызывает явную ошибку. Ресурс кэшируется по абсолютному пути, mtimes/размерам
конфигурации и весов и устройству: повторное создание пайплайна на каждой строке
не перезагружает модель. Используются `eval()` и `torch.inference_mode()`.

Для общего отчёта доступны `model_metadata`, `device`, `artifact_path`,
`trained_categories`, `unsupported_categories`, `categories`, `threshold`;
`probabilities(inp)` возвращает реальные sigmoid-оценки, кроме исходной категории.

## Оценка и ограничения

Метод оценивается общим runner на всех **208 официальных строках**, включая
противоречивые дубликаты, после фиксации кода и обучения. Метрики — общий
`run.calculate_metrics` (sklearn micro-F1) и `60 × F1`. Таблица фактических метрик,
времени, версии кода и сравнение с остальными методами находятся в
[общем отчёте](classifier-methods.md); компактные исходные результаты —
`results/classifier-methods.json`. Этот документ не подменяет их ожидаемыми
или выдуманными результатами.
`train-report.json` содержит только тренировочный loss, не качество на test.

Запуск общей оценки после обучения:

```bash
PYTHONPATH=src uv run python -m subcategory_extraction.benchmarks.compare_methods --methods semantic_encoder
```

Автоматическая разметка train, отсутствие положительных 101 и ограниченное
покрытие длинных текстов тремя окнами остаются ограничениями метода. Ни порог,
ни число эпох, ни окна не подбираются по итоговому test.

## Измеренный результат

Реальное обучение завершено на Apple M4 Pro/MPS: 4821 документ, три эпохи,
train BCE 0.352606 → 0.180750 → 0.133269. Время команды — 164.31 секунды.
На всех 208 официальных строках: micro-F1 **0.786704**, TP=284, FP=143, FN=11,
классификационные баллы 47.202/60. Validation и поиск порога не использовались.
Инференс выполнялся по 139 уникальным входам, а метрика учитывает все 208 строк.
Этот фиксированный encoder не превзошёл нативный Jev; замены лучшего baseline
или обещания качества на скрытом наборе из этого результата не следует.

## CPU и внешние расходы

Дополнительный запуск тех же весов с `SEMANTIC_ENCODER_DEVICE=cpu`:
139 уникальных входов за 0.697 с после загрузки, медиана 3.581 мс,
P95 11.158 мс на Apple M4 Pro. Все 208 наборов предсказаний совпали с MPS;
micro-F1 остался 0.786704. API-попыток нет; затраты CPU/обучения этим не обнуляются.
Точные условия и общий учёт внешних клиентов — [CPU/стоимость](cpu-costs.md).
