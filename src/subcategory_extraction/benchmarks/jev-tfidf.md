## Что проверяем и почему

Проверяем, повышает ли F1 добавление обученного локального классификатора к Jev.
Все три реализации загружаются штатным `load_pipeline`; их код находится в
`src/subcategory_extraction/{jev,tfidf,jev_tfidf}`. Старые `experiments/`,
validation/holdout-выборки и результаты прошлых моделей не используются.
Pytest и тестовый фреймворк не добавлялись и не запускались.

Заранее зафиксированный протокол:

```json
{
  "dataset": "docs/innoglobalhack_avito/public-test-dataset.parquet",
  "source_mc_id": 101,
  "rows": 208,
  "modules": ["jev", "tfidf", "jev_tfidf"],
  "jev_model": "jev-1.13.0",
  "jev_endpoint": "https://bestapi.fugue.pro/v1/systemone",
  "prompt": "src/subcategory_extraction/google_decision/prompts/google_decision_guided.md",
  "threshold": 0.5,
  "hybrid_jev_weight": 0.5,
  "validation_used": false,
  "test_parameter_search_used": false
}
```

Jev задаёт пять независимых вопросов Noul о реально предлагаемых услугах;
исходная категория не запрашивается. Используется существующий актуальный
`guided`-промпт, без переписывания под ошибки public test. Проверяются model ID,
полный набор ответов и конечные числовые вероятности [0,1]. Кэш содержит только
фактические ответы API; ключ кэша включает endpoint, модель, текст и вопросы.
Он сохраняет одинаковые ответы Jev для baseline и гибрида, включая одинаковые
описания с противоречивой разметкой. Дубликаты оценочного набора не удаляются.

Локальная часть — word TF-IDF (1–2 grams, min_df=2, max_features=30,000,
sublinear_tf) и логистические регрессии C=4, max_iter=500. Обучение — на всех
доступных официальных train-группах, без validation/holdout и без поиска порога.
Нормализованные дубликаты объединены; из обучения по одним только текстам
исключены компоненты, связанные с public test при char_wb TF-IDF cosine >=0.85.
После исключения 33 описаний осталось 4,821 из 4,854 уникальных train-текстов.
Метки public test не использовались для обучения или настройки.

Гибрид считает `0.5 * P(Jev) + 0.5 * P(TF-IDF)`. Если для категории нет
обученной локальной головы (101), остаётся вероятность Jev. Один глобальный
флаг split и regex hard gate не используются.

## Запуск

```bash
uv sync
PYTHONPATH=src uv run python -m subcategory_extraction.benchmarks.train_jev_hybrid
PYTHONPATH=src uv run python -m subcategory_extraction.benchmarks.compare_jev_hybrid
```

Нужен `BESTAPI_API_KEY` в корневом `.env`. Артефакт — `out/tfidf.json`,
описание обучения — `out/jev-hybrid-training.json`, фактический обучающий набор —
`out/hybrid-training.jsonl`, реальные ответы API — `out/jev-cache/`.
Итоговый отчёт — `out/jev-hybrid-comparison.json`, с хешами данных, артефакта и
промпта, всеми предсказаниями, временем и разделением cache hits/API requests.
Cached latency не является оценкой холодного инференса гибрида.

## Результаты по версиям

| Версия | Модуль | micro-F1 | Баллы / 60 | TP | FP | FN |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| cd0f310 + рабочие изменения | jev | **0.846154** | **50.769231** | 286 | 95 | 9 |
| То же | tfidf | 0.778462 | 46.707692 | 253 | 102 | 42 |
| То же | jev_tfidf | 0.842262 | 50.535714 | 283 | 94 | 12 |

Метрика — `run.calculate_metrics`, то есть sklearn `average="micro"` и
`zero_division=0` на шести одинаково упорядоченных колонках, баллы `60 * F1`.
Это оценка классификации, а не генерации и не полного 100-балльного результата.
В исходном cd0f310 модулей Jev/гибрида не было: их исторический балл не выдуман.
Прежние результаты на других обучающих разбиениях сюда не перенесены.

- `src/main.py` с `jev_tfidf` и существующим `sample_llm` обработал
  `data/input.json`: получен черновик 104 с непустыми заголовком и текстом,
  сохранённый в `out/jev-hybrid-live.json`. Это сквозной smoke, не F1 на test.

- Общая модульная метрика совпала со штатной `run.calculate_metrics` на
  контрольном примере: TP=4, FP=2, FN=1, micro-F1=8/11, баллы=43.636364/60.

## Выводы

Фиксированное усреднение не улучшило Jev: потеряны три TP при сокращении одного
FP. Поэтому в `config.json` выбран чистый `jev`, а `jev_tfidf` оставлен как
реальный воспроизводимый эксперимент, не как якобы улучшенная production-модель.
Вес и порог после просмотра результата не подбирались. Это лучший из трёх
проверенных вариантов на данном public set, а не доказанный максимум F1 на
скрытых данных. Известные противоречия меток одинаковых объявлений сохраняются.

### Ограничение сквозной оценки генератора

Дополнительный штатный `src/run.py --config out/selected-smoke.config.json`
с выбранным `jev` и `sample_llm`, ограниченный одной строкой для проверки
интеграции, завершился HTTP 429 от Gemini после четырёх штатных попыток.
Оценщик правильно не записал новую итоговую метрику. Это ограничение генератора,
не ошибка завершившегося классификационного бенчмарка 208 строк. Полная оценка
F1 по сгенерированным drafts на 208 строках этим запуском не измерена.
Успешный отдельный CLI-smoke гибрида выше не выдаётся за такой полный прогон.

### Независимая проверка TF-IDF и конкурсных файлов

По отдельному запросу проверено измерение без новых вызовов Jev и без validation.
Оба использованных файла в `docs/innoglobalhack_avito/` побайтно совпадают с
исходными файлами пользователя в соседней `innoglobalhack_avito/`:
train SHA-256 `b7118d68086624fbeab43839f22a635d4e325e4ee339f22d4aa0ad3c2e986615`,
test SHA-256 `65b5a45a98b577d853a928932bbbdf8bd9bdeb469ded3016faace4d11f3eabaa`.

Эталоны заново прочитаны из реального Parquet, независимо от сохранённого
отчёта; micro-F1 заново посчитана sklearn по бинарной матрице шести категорий:
0.7784615384615384, TP=253, FP=102, FN=42. Все 208 строк и 295 положительных
меток учтены. Названия категорий и порядок эталонов совпали с отчётом.

На фактических 4,821 обучающих описаниях независимо заново обучены нативные
TfidfVectorizer и LogisticRegression с теми же фиксированными параметрами.
Словарь совпал; максимальные расхождения IDF, коэффициентов и вероятностей —
ровно 0. Все 208 предсказаний нативного sklearn, загруженного JSON-артефакта
и сохранённого отчёта совпали. Нормализованных точных пересечений фактического
train с test нет. Подробности — `out/tfidf-measurement-audit.json`.

Таким образом, результат относится к конкретному word TF-IDF + логистической
регрессии с порогом 0.5, а не ко всем возможным классификаторам на TF-IDF.
Отдельного подтверждения скрытого конкурсного набора эта проверка не даёт.
