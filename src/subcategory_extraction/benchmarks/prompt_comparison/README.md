# Бенчмарк: качество выделения и сравнение промптов

Сервис: subcategory_extraction.

## Что проверяем

Настоящий `run()` выбранного модуля на общей validation-выборке официального
`docs/innoglobalhack_avito/public-train-annotated.jsonl`.
SHA-256: `b7118d68086624fbeab43839f22a635d4e325e4ee339f22d4aa0ad3c2e986615`.
По умолчанию берём 100 групп через `validation_sample(size=100, seed=43)`:
точная нормализация NFKC/casefold/ё→е/whitespace, 4854 уникальных описания,
старое разбиение 70/15/15 с seeds 42 и 43, выборка из 728 validation-групп.
Идентификаторы выбранных групп сохранены в отчёте. Близкие, но не идентичные
шаблоны отдельно не группируются; независимость таких шаблонов не гарантируется.
Новый Google-модуль здесь не обучается, порог автоматически не подбирается.

Главная метрика — micro-F1 через sklearn по категориям 101–106; баллы за
классификацию — 60 × micro-F1. Также сохраняются TP/FP/FN и precision/recall/F1
для каждой категории. Macro-F1 вычисляется по всем шести столбцам, включая
101, которой нет в положительных метках официального train.

Правило лучшего промпта: на одинаковых входах максимальный micro-F1; при
равенстве — первый из переданных через `--prompts`. При незавершённом
сценарии итогового F1 и лучшего промпта нет. Конфигурация автоматически не
меняется. `guided` и 0.5 пока являются начальными настройками.

## Запуск

```bash
uv run python src/subcategory_extraction/benchmarks/prompt_comparison/run.py
uv run python src/subcategory_extraction/benchmarks/prompt_comparison/run.py --prompts guided --size 100
uv run python src/subcategory_extraction/benchmarks/prompt_comparison/run.py --module tfidf --size 100 --report /tmp/tfidf-validation.json
```

Для Google нужны ключ и настройки из `.env`. По умолчанию выполняется до
200 настоящих `run()` Google: по 100 на baseline/guided. Для другого модуля
данные, метрики и проверка ответа остаются теми же; сценарий без промпта — один.
`--size`, `--module`, `--prompts`, `--report` задают параметры явно.
Актуальный отчёт — [rebuild-results.json](rebuild-results.json); прежний
[results.json](results.json) сохранён отдельно как исторический.
Ответы записываются после каждого завершённого `run()`. Ошибки и прерывание
дают failed, без итоговой метрики. Возобновления и подстановки кэша нет.

Время измеряется `perf_counter()` вокруг настоящего `run()`: включает
сетевые повторы и ожидания квоты, исключает создание экземпляра, подготовку
выборки и запись отчёта. Стоимость заполняется вручную; скрипт её не считает.
