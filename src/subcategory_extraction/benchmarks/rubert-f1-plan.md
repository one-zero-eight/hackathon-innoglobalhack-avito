## Что сравниваем

Собственный компактный студент `cointegrated/rubert-tiny2`, revision
`e8ed3b0c8bbf4fb6984c3de043bf7d2f4e5969ae`, остаётся единственной моделью
production-классификатора. Новый модуль — `semantic_encoder_f1`; CPU обязателен,
учитель и внешние API при inference не нужны. Генератор черновиков не меняется.

Формула соответствует правилам: `micro-F1 = 2TP / (2TP + FP + FN)` по
дополнительным mcId, баллы классификации `60 × micro-F1`. Проверяется совпадение
общего sklearn-оценщика и прямых счётчиков. Это не обещание результата лидерборда:
скрытые данные организаторов недоступны, а полный генератор здесь не оценивается.

## Данные и границы вывода

- Источник — только InnoGlobalHack `docs/improved_dataset/train.jsonl`, 4851 уникальных описаний, SHA-256 `d365141906cd7e2a1d66792aa2e37661d8bcdcd0a4bbaf3781649a9108238b76`.
- Сохраняется прежнее групповое разделение: 3196 train,1043 validation,612 control. Семейства похожих объявлений не перераспределяются после просмотра результатов. Прежний control уже использовался в опыте порогов; это **повторно используемый внутренний контроль**, не новый независимый holdout.
- Все решения по LR, checkpoint, архитектуре, review, дистилляции, порогам и seed42 фиксируются по validation **до** общей оценки. Параметры не меняются после просмотра control или диагностических119.
- Для понятного сопоставления все зафиксированные студенты и исходный RuBERT оцениваются на одних119 описаниях `reviewed_test.parquet`. Это диагностическая предварительная переразметка, не независимо проверенный ручной test. Исходный mcId отсутствует и явно принимается равным101.
- У исходного RuBERT на всех4851 строках нельзя честно считать control F1: control входил в его train. Для него публикуется только диагностическая119 оценка. Отдельный original-split-baseline обучен на тех же3196, что новые студенты, и пригоден для внутреннего сравнения.
- Поддержка положительного класса101 не доказана: исходная категория во всём train —101. Она не подбирается порогом и исключается из ответа, когда совпадает с входным mcId.

## Выполненные изменения

### Обучение и выбор checkpoint

Grid learning rate `[1e-5,3e-5,5e-5]`, seed42, AdamW `weight_decay=0.01`,
batch16, линейные warmup10% и decay, gradient clipping1. Максимум6 эпох,
минимум2, patience2. Сохраняется самый ранний лучший checkpoint по validation
micro-F1 при0.5, а не автоматически последняя эпоха. Все веса encoder обучаются.
Финальная конфигурация дополнительно проверяется на seed43 и44; production
заранее закреплён за seed42, не выбирается самый удачный seed постфактум.

### Устойчивые пороги

Пороговый поиск использует только validation probabilities на CPU.
`GroupKFold(3)` удерживает известные близкие validation-шаблоны вместе;
пороги каждого fold подбираются без меток его отложенной части. Сравниваются
fixed0.5, global и per-category с shrinkage к0.5:25/50/75/100% отклонения.
Выбор — pooled threshold-crossfit micro-F1; усложнение требует минимум0.002
прироста относительно fixed. После выбора стратегия fit на всей validation.
**Это cross-fitting порогов, не OOF encoder:** checkpoint ранее выбран на той
же validation, поэтому число не выдаётся за независимую оценку модели.

### Трудные отрицательные примеры

[Сохранённая смысловая проверка](results/rubert-hard-negatives.json): полностью
прочитаны64 train-описания, выбранные по реальным CPU-вероятностям baseline.
Подтверждены35 keep-примеров, из них28 пустых и7 частичных; им назначен
умеренный вес1.5. Ещё29 случаев неоднозначны: исходные метки и вес1 сохранены.
**Исправлений меток —0:** построчное происхождение пользовательских исключений
отсутствует, поэтому спорные решения не заменялись новым автоматическим правилом.
Эта проверка ассистента не является независимым ручным gold. Все исходные
описания, порядок и labels защищены SHA; review не применяется к validation/test.

### Окна и обучаемая агрегация

Baseline — прежние mean/first-middle-last, максимум3 окна по512 токенов.
Альтернатива — до6 смежных непересекающихся окон по512 с label-wise attention.
При достаточном бюджете сохраняются все токены. Сверх бюджета равномерно
выбираются фрагменты с первым/последним; **не обещается полное покрытие** текстов
любой длины. Attention учитывает количество реальных токенов и инициализируется
эквивалентно token-weighted mean. Эвристического вырезания SEO/отрицаний нет.

### Дистилляция

Локальный сильный по архитектуре учитель —
[`DeepPavlov/rubert-base-cased`](https://huggingface.co/DeepPavlov/rubert-base-cased/tree/4036cab694767a299f2b9e6492909664d9414229),
пин revision `4036cab694767a299f2b9e6492909664d9414229`.
Он дообучается только на reviewed train: mean/coverage256/3 окна, lr2e-5,
batch8, до3 эпох, минимум2, patience1. Сохраняется лучший validation checkpoint.
Фактическое качество учителя оценивается, а не предполагается из размера.
Студент обучается с hard multilabel BCE и soft BCE по teacher logits только
для train, `alpha=0.5`, `T=2`, с множителем `T²`. Учитель не получает control
или диагностический test при обучении и не нужен в CPU-инференсе студента.

## Воспроизведение

Установить зависимости `uv sync`. Веса/кэши/артефакты `out/` не включаются в Git.
Данные и SHA/provenance уже сохранены. Сначала воспроизвести прежние артефакты
по [improved-dataset.md](improved-dataset.md) и разбиение/исходный split-baseline
по [rubert-thresholds.md](rubert-thresholds.md). Затем из корня проекта:

```bash
HF_HUB_DISABLE_XET=1 TOKENIZERS_PARALLELISM=false PYTHONPATH=src uv run python -m subcategory_extraction.benchmarks.improve_rubert_f1 --stage train
HF_HUB_DISABLE_XET=1 TOKENIZERS_PARALLELISM=false PYTHONPATH=src uv run python -m subcategory_extraction.benchmarks.improve_rubert_f1 --stage evaluate
```

`--device auto` выбирает MPS для обучения, если доступен; `--device cpu`
разрешает полностью CPU-обучение. Калибровка и production inference — толькоCPU.
`out/rubert-f1-plan/protocol.json` фиксирует параметры до опытов,
`frozen-selection.json` фиксирует выбор до общей оценки. Уже завершённые
кандидаты переиспользуются лишь с идентичной спецификацией/хешами; чужие или
частичные артефакты не подменяются. Общая оценка не перезаписывается повторно.

Модуль выбирается в `config.json` через `subcategory_extraction: semantic_encoder_f1`.
Веса по умолчанию — `out/rubert-f1-plan/selected`; другой путь задаётся
`RUBERT_F1_ARTIFACT_PATH`. Установите `RUBERT_F1_DEVICE=cpu`.
`calibration.json` обязателен и привязан к SHA метаданных encoder;
отсутствие весов/порогов — явная ошибка, не fallback. Тексты и JSON-контракт
входа/выхода не меняются. `sample_llm` остаётся внешним генератором.
