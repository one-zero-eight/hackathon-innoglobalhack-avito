# Бенчмарк: ключевые фразы, выученные на Юле

Сервис: subcategory_extraction
Автор: fih
Дата: 2026-11-14

Проверяем перенос с Юлы на InnoGlobalHack без словаря SplitShift. Это
отдельный эксперимент на внешнем корпусе по запросу пользователя.

## Данные и запуск

[Описание и контрольные суммы снимков](data/README.md). Для обучения
подключён [Youla с разметкой, 859 строк](data/youla-859-annotated.jsonl).
Размеры 100, 200, 400 и 800 получаем, беря первые строки в исходном порядке.
[Исходные объявления Youla, 1 469 строк](data/youla-1469-raw.jsonl) и
[профили Яндекса, 1 492 строки](data/yandex-1492-raw.jsonl) доступны
для отдельной разметки и сравнения источников.

Оценка использует 494 validation и 485 holdout объявлений из официального
`public-train-annotated.jsonl` InnoGlobalHack. Дедупликация учитывает Unicode,
регистр, ё → е и пробелы. Разбиение дополнительно группирует описания
без чисел и пунктуации. Пороги выбираются на validation, итоговые метрики
считаются на holdout. Официальный Parquet зарезервирован.

```sh
mkdir -p out
for n in 800 859; do
  PYTHONPATH=src uv run python -m subcategory_extraction.benchmarks.run_youla_keywords \
    --train src/subcategory_extraction/benchmarks/data/youla-859-annotated.jsonl --size "$n" \
    --report "out/youla-category-cutoffs-$n.json" --artifact "out/youla-cutoffs-$n-model.json"
done
```

Отчёты: [800 строк](results/youla-category-cutoffs-800.json) и
[859 строк](results/youla-category-cutoffs-859.json).
Артефакт для `learned_keywords` использует сочетание выученных совпадений
и полного TF-IDF при пороге 0.50. Таблицы с отдельными порогами описывают
результаты анализа. Для запуска модуля укажите путь к артефакту через
`LEARNED_KEYWORDS_ARTIFACT`.

## Выводы

Словарь униграмм и биграмм строится по объявлениям Юлы. Для каждой категории
берём до 40 фраз, которые чаще встречаются в положительных примерах,
и ранжируем их по χ². Логистическая регрессия использует бинарные
признаки присутствия фраз. Вся лексика и веса выучены на Юле.

На этом holdout совпадения дали на 0.1093 micro-F1 больше, чем TF-IDF.
Добавление TF-IDF к совпадениям снизило результат. Встроенный вариант
проверен через загрузчик конфигурации: его прогнозы на всех 485 строках
совпали с прогнозами обученной комбинированной модели.

## Кривая обучения на расширенном корпусе

Из `out/youla-1382.jsonl` взяли все 100 записей с сохранённой разметкой
и 300 новых записей после перемешивания с seed 52. URL и описание
проверили перед переиспользованием меток. В выборке из 400 записей все
группы нормализованных описаний различны и не пересекаются с исходным
train InnoGlobalHack. Новые записи размечены тем же Gemini Decision 1
с порогом 0.50, в пределах 45K входных токенов за скользящую минуту.

Подвыборки вложены (первые 100, 200 и 400 записей). Дополнительно
проверяем локальный TF-IDF до пяти слов перед совпадением и до пяти
после фразы из двух слов. Словарь, IDF и коэффициенты fit на Юле.
Порог выбираем на 494 validation объявлениях InnoGlobalHack или
оставляем 0.50 для сравнения с предыдущим прогоном. Holdout — те же
485 объявлений.

При отказе API строка пропускается. Для восстановления размера выборки
берём следующие строки в том же случайном порядке.

Одна запись отклонена API, вместо неё размечена следующая. 300 новых
ответов использовали 375 334 входных токена. Все три прогона оценены
на одних и тех же 485 объявлениях.

| Признаки | 100, порог 0.50 | 200, порог 0.50 | 400, порог 0.50 | 400, порог по validation |
| --- | ---: | ---: | ---: | ---: |
| TF-IDF всего объявления | 0.7018 | 0.7854 | 0.8070 | 0.8070 |
| Выученные совпадения | 0.8111 | 0.8917 | 0.9024 | 0.9024 |

### Расширение до 800 объявлений

На том же holdout из 485 объявлений отдельные логистические регрессии
для каждой категории дали micro-F1 0.9168 на выученных совпадениях
(1130 TP, 115 FP, 90 FN), против 0.9024 на 400 объявлениях.
Порог 0.50 использован для сопоставления размеров выборки.
Остальные результаты при 0.50: полный TF-IDF 0.8416, совпадения с полным
TF-IDF 0.9108, совпадения с локальным TF-IDF 0.9128, все признаки 0.9088.
[Полный отчёт для 800 строк](results/youla-category-cutoffs-800.json).

### Диагностика штукатурных работ (102)

Из 800 обучающих объявлений 183 имеют метку 102, это самая редкая
целевая категория в этой выборке. При пороге 0.50 на holdout пропущено
49 из 258 меток 102. Корень «штукатур» встретился в 7 из 49 пропусков
и в 192 из 209 верных срабатываний. У пропусков медиана числа совпадений
с выученными признаками — 7 против 17 у верных срабатываний.
В 31 из 49 пропусков встречается корень «шпакл» или «шпатл».

Подбирали порог только для 102, оставляя остальные категории на 0.50.
Лучший по micro-F1 на validation среди проверенных порогов — 0.25.
На holdout F1 для 102 вырос с 0.8636 до 0.8818 (220 TP, 21 FP, 38 FN),
общий micro-F1 — с 0.9168 до 0.9202. Порог 0.20 дал на holdout
0.9215, но уступил 0.25 на validation.

### Автоматический подбор порога каждой категории

Перебор порогов от 0.00 до 1.00 с шагом 0.01 оптимизирует общий micro-F1
на 494 validation объявлениях. Для текущего значения F1 независимо
выбирается порог каждой категории, максимизирующий
`2 × TP − F1 × число предсказанных меток`. Значение F1 пересчитывается
до сходимости. Итоговые пороги применяются к тем же 485 holdout объявлениям.
