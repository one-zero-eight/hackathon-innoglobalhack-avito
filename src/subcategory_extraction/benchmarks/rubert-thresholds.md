# Подбор порогов RuBERT-tiny2

Сервис: `subcategory_extraction`. Дата: 2026-11-14.
Ветка: `leo/feature/rubert-thresholds`.

## Протокол

- Источник: только `docs/improved_dataset/train.jsonl`, 4851 описаний с предварительной автоматической разметкой. Заголовки и диагностический test из 119 описаний не используются.
- Старые task-веса обучены на всём train; их нельзя честно калибровать на подвыборке того же train. Поэтому один новый encoder обучается с исходного pretrained checkpoint на отдельном train, без validation/control.
- NFKC/casefold/ё→е/пробелы используются только для группировки. Рёбра — точные совпадения или cosine ≥0.85 по `char_wb` TF-IDF, ngrams `(3,5)`, `min_df=2`, `max_features=40000`. Целые связные компоненты делятся `GroupShuffleSplit`: сначала 15% групп в control (seed42), затем 15/85 оставшихся в validation (seed43). Размеры частей по строкам могут отличаться от 70/15/15. Метки не участвуют в разбиении. Отсутствие известных рёбер между частями не гарантирует отсутствие всех смысловых шаблонных утечек.
- Обучение не менялось: три эпохи, последний checkpoint, BCE, AdamW `lr=3e-5`, seed42, batch16; encoder и голова дообучаются целиком. Сохраняется исходная схема окон начала/середины/конца. Единственная настраиваемая часть опыта — пороги.
- На CPU вычисляются validation-вероятности. Сравниваются `fixed` 0.5, точный общий порог и покатегорийный coordinate ascent с общей целью **micro-F1**, а не средним F1 классов. Равные score переключаются атомарно, сравнение `>=`; принимается только строгое улучшение. При равенстве методов предпочтение fixed → global → per_category. Покатегорийный поиск ограничен 20 проходами, это не заявление о глобальном оптимуме вектора порогов.
- Категория101 — исходная категория всех примеров, положительных примеров101 нет. Она исключена из подбора, её порог остаётся0.5; поддержка задачи для других исходных категорий этим опытом не доказана.
- `calibration.json` сохраняется **до первого inference на control**. Выбор метода и порогов после этого не меняется; control используется один раз для итогового сравнения всех заранее определённых вариантов.
- Все сравнения выполняются на одних весах и строках. Это внутренний holdout предварительной разметки, не независимо подтверждённый ручной эталон. Его F1 нельзя напрямую сравнивать с прежним F1 на диагностических119 строках.

Фактические части: **3196 train / 1043 validation / 612 control**.

`d365141906cd7e2a1d66792aa2e37661d8bcdcd0a4bbaf3781649a9108238b76`.

**Прирост не подтвердился.** Покатегорийный вариант потерял 0.009509
micro-F1 на control относительно 0.5. Он остаётся воспроизводимым
экспериментом, а не рекомендованной заменой baseline. Общий порог повысил
precision с 0.869748 до 0.925256, но снизил recall с 0.955017 до 0.885236;
итоговый micro-F1 тоже ниже. После просмотра control пороги не менялись.
Default-конфиг и прежние task-веса не заменялись.

Распределения частей заметно различаются: категория106 положительна
в 740/1043 validation-строках и 276/612 control-строках; категория103 —
в 297/1043 и 349/612 соответственно. [INFERENCE] Крупные шаблонные
компоненты и такой сдвиг распределения могли сделать подбор нестабильным.
Низкий validation-порог106 на control увеличил FP106 с 61 до 119.
Причинность одним опытом не доказана; повторно подстраиваться под этот
control для доказательства улучшения нельзя.

## Проверки и CPU

- 144 детерминированных случая поиска: global сопоставлен с полным перебором, TP/FP/FN всех вариантов — с прямым применением порогов; проверены равные score,0/1, отсутствие positives, перестановки категорий и некорректные входы.
- Реально выполнены 612 CPU-вызовов нового `run()`, все ответы совпали с применением сохранённых порогов к вероятностям. Хеш calibration до и после control совпал.
- Реальная динамическая загрузка через `main.load_pipeline` без аргументов конструктора выбрала `semantic_encoder_calibrated` и CPU; исходный mcId исключён.
- Отвергнуты 8 неверных calibration: bool-версия, чужой metadata hash, неизвестный метод, bool/NaN/вне диапазона в пороге и неполный набор классов. Проверена независимость возвращаемой копии model_metadata. Одноразовый smoke-скрипт удалён; тестовый фреймворк не добавлялся.
- Последовательный `run()` на локальном arm64 CPU, 10 PyTorch-потоков: медиана **5.033 мс**, p95 nearest-rank **12.230 мс**, среднее **5.892 мс**. Замер прогрет сбором вероятностей и не включает загрузку. Это не SLA для произвольного CPU.
- Классификатор не сделал внешних API-запросов. Генерация черновиков не запускалась.

## Артефакты и воспроизведение

Из корня `hackathon-avito-latest`:

```bash
HF_HUB_DISABLE_XET=1 TOKENIZERS_PARALLELISM=false PYTHONPATH=src .venv/bin/python -m subcategory_extraction.benchmarks.tune_semantic_thresholds
```

Обучение использует доступный MPS или CPU; весь подбор и контрольный inference принудительно идут на CPU. Новые веса сохраняются в `out/rubert-thresholds/encoder`, пороги — в `calibration.json` рядом с весами. Разбиение, полные train/validation/control JSONL и manifest — в `out/rubert-thresholds/`. Старые веса и default-конфиг не изменяются. При повторном опыте задайте новые `--output` и `--report`: скрипт не перезаписывает существующие результаты и не подстраивает пороги по уже просмотренному control.

[Машиночитаемый отчёт](results/rubert-thresholds.json) содержит SHA входа/частей/кода, номера исходных строк, вероятности и эталоны validation/control, train-report, выбранные пороги, метрики и время реального `run()`. Перенос `calibration.json` к несовместимым метаданным encoder отвергается; без calibration новый модуль не делает молчаливого fallback на0.5.

Для воспроизведения экспериментального варианта выберите в `config.json`
(это не рекомендация заменить baseline: прирост на control не подтвердился):

```json
{
  "subcategory_extraction": "semantic_encoder_calibrated",
  "draft_generation": "sample_llm"
}
```

```bash
SEMANTIC_ENCODER_DEVICE=cpu PYTHONPATH=src .venv/bin/python src/main.py --input data/input.json --output out/output.json
```

Новый модуль по умолчанию берёт `out/rubert-thresholds/encoder`; другой артефакт можно выбрать через `SEMANTIC_ENCODER_ARTIFACT_PATH`. Классификация не требует GPU или внешнего API. `sample_llm` — отдельный внешний генератор: этот опыт не переводит генерацию черновиков в офлайн CPU-режим и не измеряет её качество или расходы.
