# Jev + TF-IDF → сильный арбитр спорных категорий

Сервис: `subcategory_extraction`  
Модуль: `jev_arbiter`  
Дата: 2026-11-14

## Зафиксированный метод и routing

Один заранее заданный вариант без validation/holdout и подбора по официальному
тесту. Baseline — существующий нативный Jev (по умолчанию `jev-1.13.0`),
порог **p ≥ 0.5**. Локальный сигнал — существующие вероятности TF-IDF голов;
для сравнения также применяется фиксированный порог **0.5**, а не сохранённый
в артефакте альтернативный порог.

Для каждой eligible категории (все `MICROCATEGORIES`, кроме исходной) routing
задан заранее:

1. Jev p находится в **[0.30, 0.70]**, обе границы включены; **или**
2. для категории есть настоящая локальная обученная голова и решения
   Jev/TF-IDF при 0.5 различаются.

Локальная вероятность категории вне `local.trained_categories` не используется
в routing. В текущем официальном train исходная категория всегда 101, поэтому
голова 101 не поддержана локальными данными: чужими данными она не подменяется.
Если на другом входе 101 eligible, маршрут для неё возможен по неопределённости
Jev, но не по фиктивному локальному разногласию.

Если routed пуст, `run()` возвращает подлинный результат baseline, **без вызова
арбитра**. Иначе выполняется **один** запрос сильной генеративной модели на всё
объявление и точный список routed категорий. Передаются полный `description`,
исходный `mcId` и таблица категорий с названиями и существующими
`CATEGORY_EXAMPLES`. Вероятности и метки baseline/local арбитру не передаются,
чтобы не якорить решение. Промпт — `jev_arbiter/prompts/arbitrate.md`.

Арбитр независимо определяет текущее предложение услуги по исходному тексту,
учитывая явно предложенные этапы комплексного ремонта, но не делая вывод
о конкретных работах только из слов «под ключ». Формат ответа:
`{"decisions": [{"mcId": 104, "offered": true, "quote": "..."}]}`.
Все поля обязательны; корень и вложенные объекты имеют Pydantic
`ConfigDict(extra="forbid", strict=True)`. `mcId` — настоящий integer общей
таблицы, не bool; `offered` — настоящий bool. Список содержит ровно по одному
решению на каждую routed категорию: точный набор, без дубликатов и посторонних ID.

Положительное решение требует непустой цитаты — **точной непрерывной подстроки**
исходного description, включая пробелы, регистр и пунктуацию. Для false разрешён
`quote=""`; непустая отрицательная цитата тоже проверяется на точное совпадение.
Пробельные цитаты отвергаются. Нормализация пробелов не выполняется.
Динамическая Pydantic-проверка знает исходный текст и routed; общий клиент
проводит её до сохранения реального API-ответа в кэш. Ошибки API, JSON, схемы
или цитат видимы вызывающему коду: нет тихого baseline fallback, повторов и `[]`
вместо сбоя.

Вердикты заменяют **только routed категории**, не-routed решения Jev остаются
неизменными. Бинарные ответы арбитра не выдаются за калиброванные вероятности:
интерфейс метода — только итоговый `run() -> list[int]`, без синтетического
метода вероятностей гибрида.

## Запуск и вход

Класс `SubcategoryExtractionPipeline(BasePipeline)` создаётся без аргументов.
В `config.json` выбирается обычный модуль:

```json
{
  "subcategory_extraction": "jev_arbiter",
  "draft_generation": "sample_llm"
}
```

Пример JSON входа (не строка официального теста):

```json
{
  "description": "Ремонт квартир. Монтаж сантехники и укладка плитки.",
  "mcId": 101
}
```

Из корня репозитория:

```bash
PYTHONPATH=src uv run python -m subcategory_extraction.benchmarks.compare_methods --methods evidence_jev jev_arbiter
```

## Окружение и provenance

- `BESTAPI_API_KEY` — секрет для реальных API-запросов при промахе кэша.
- `JEV_MODEL` (по умолчанию `jev-1.13.0`), `JEV_ENDPOINT`, `JEV_TIMEOUT`
  (60 секунд), `JEV_CACHE_DIR` (`out/jev-cache`) — штатный нативный клиент.
  Baseline сохраняет штатную поддержку `JEV_PROMPT_PATH`; для зафиксированного
  сравнения используется существующий guided-промпт без override.
- `STRUCTURED_LLM_MODEL` (по умолчанию `gpt-6.1-terra`),
  `STRUCTURED_LLM_ENDPOINT`, `STRUCTURED_LLM_TIMEOUT` (90 секунд),
  `STRUCTURED_LLM_CACHE_DIR` (`out/structured-llm-cache`) — общий JSON Schema
  клиент. По умолчанию BestAPI chat/completions, strict JSON Schema,
  `max_completion_tokens=4096`, temperature отдельно не задаётся.
- `TFIDF_ARTIFACT_PATH` — штатный JSON-артефакт, по умолчанию `out/tfidf.json`.
  При его отсутствии/некорректности — явная ошибка; обучение автоматически не
  запускается. Используется общий подготовленный официальный train; для
  текущего сравнения после исключения 33 exact/near train-компонент,
  касающихся публичного теста при cosine ≥ 0.85, остаётся 4821 уникальный пример.
  Метки теста для удаления пересечений и обучения не используются.
- `.threshold=0.5`, `.uncertainty_low=0.30`, `.uncertainty_high=0.70`
  фиксированы кодом; `JEV_THRESHOLD` и порог артефакта не меняют routing.
- Для runner доступны `.baseline`, `.local`, `.arbiter`,
  `.last_routed_categories`, `.last_arbiter_used`, `.last_baseline_probabilities`,
  `.last_local_probabilities` (только обученные головы), `.last_decisions`,
  `.arbitration_prompt`. Настоящие model IDs, endpoint, API usage и cache-hit
  доступны на `.baseline.client`/`.arbiter`; `.arbiter.last_model` хранит
  проверенный фактический ID. `last_arbiter_used` означает участие арбитра
  в вычислении, в том числе при чтении настоящего ответа из кэша.
- Импорт не делает сетевых запросов; локальный артефакт читается при создании
  экземпляра. На объявление — один нативный запрос Jev и не более одного
  запроса арбитра, либо соответствующие настоящие ответы из общих кэшей.
  Собственного API-клиента или протокола кэширования у метода нет.

## Оценка и ограничения

Официальный тест сохраняется полностью: все 208 строк
`public-test-dataset.parquet`, включая противоречивые дубликаты. Метрика — общий
`run.calculate_metrics`: sklearn micro-F1 и `60 * F1`. Ни границы routing,
ни пороги, ни промпт не подбираются по этим меткам; отдельного holdout нет.

Общий запуск был выполнен, но запрос к арбитру завершился HTTP 401 от BestAPI.
Предоставленный ключ также отклонён endpoint списка моделей как `invalid api key`.
Полного результата/F1 этого метода нет; baseline не выдан за результат арбитража.
Статус и сравнение доступных методов — [общий отчёт](classifier-methods.md).

Цитата гарантирует лишь совпадение текста, не правильность семантического
вердикта. Уверенные ошибки Jev вне routing могут остаться без исправления;
ошибки локального сигнала способны увеличить число обращений к арбитру.
Если маршрутизированы многие категории, задержка/стоимость приближаются к
полному арбитражу. Полный текст не обрезается, поэтому ограничения контекста
и длины JSON-ответа приводят к явной ошибке, а не скрытой смене метода.
