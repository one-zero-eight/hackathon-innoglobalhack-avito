# Логистическая регрессия на фрагментах объявления

## Текущий статус

Эксперимент в работе на ветке `fih/feature/snippet-logistic-regression`.
Реализация находится в [pipeline.py](pipeline.py), групповая проверка —
в [fold_train.py](fold_train.py). Старый словарь, окна до 11 токенов с
обрезкой `before` и объединение бинарных признаков дали **0.9183 micro-F1**
на пяти групповых фолдах (4 966 объявлений). Объединённый набор включает
публичный test организаторов. Результат служит внутренней оценкой.

Повторный прогон воспроизвёл исходные предсказания. Для **650 из 972**
пропущенных меток хотя бы одно окно прошло порог категории, а объединённый
вектор объявления — нет. В 619 случаях такое окно открыл якорь этой
категории. Для 306 пропусков все окна остались ниже порога, ещё для 16
окна не нашлись. Высокий балл отдельного окна иногда отражал смежную
услугу. Анализ ограничен пропусками и использует пороги, подобранные
для объединённых признаков. Локальные результаты лежат в
`out/snippet-folds/old-dictionary.json` и `out/snippet-folds/missed-windows.jsonl`
от корня репозитория.

На тех же фолдах проверены два ручных словаря и максимум оценки окна.
Лучший результат **0.9323 micro-F1** дал старый словарь с максимумом
оценки окна. Подробности и команда в разделе ниже.

## Влияние длины окна, числа ключей и локальных признаков

Каждый вариант меняет один параметр базовой модели (7 слов, 40 ключей).
Порог каждой категории подбирался на validation. Ниже — результаты
подбора, результаты бенчмарков находятся в существующих сценариях.

| Вариант | Слов | Ключей на категорию | Уникальных ключей | Validation micro-F1 |
| --- | ---: | ---: | ---: | ---: |
| pairs | 7 | 40 | 99 | 0.9384 |
| pairs | 3 | 40 | 99 | 0.9265 |
| pairs | 5 | 40 | 99 | 0.9369 |
| pairs | 9 | 40 | 99 | 0.9420 |
| pairs | 11 | 40 | 99 | 0.9429 |
| pairs | 7 | 20 | 59 | 0.9365 |

| pairs | 7 | 160 | 367 | 0.9551 |

`priority` добавляет признак совпадения с одним из десяти первых ключей
своей категории. `split` ограничивает окно знаками .!?;,: и переводами строк.
`category` добавляет признаки окон на ключах своей категории поверх общих
признаков варианта `split`. Выбран вариант с 7 словами и 160 ключами.
Лучшие параметры из разных серий пока не объединялись.

## Сравнение четырёх комбинаций на общих бенчмарках

```bash
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
PYTHONPATH=src uv run python -m subcategory_extraction.snippet_logistic_regression.train --matrix-dir out/snippet-matrix
for pair in 7x40 7x160 11x40 11x160; do
  export SNIPPET_LOGISTIC_ARTIFACT="out/snippet-matrix/$pair.json.gz"
  for scenario in classifier_methods improved_dataset; do
    uv run python "src/subcategory_extraction/benchmarks/$scenario/run.py" --offline \
      --methods snippet_logistic_regression --report "out/snippet-matrix/$pair-$scenario.json"
  done
  uv run python src/subcategory_extraction/benchmarks/response_time/run.py \
    --module snippet_logistic_regression --size 10 --report "out/snippet-matrix/$pair-response_time.json"
done
unset SNIPPET_LOGISTIC_ARTIFACT
```

Все четыре комбинации заданы до запуска. Пороги каждой комбинации
подбираются внутри исходного train. Артефакты сетки сохраняются в `out/`
как временные результаты. Таблицы сравнений находятся в существующих
сценариях бенчмарков.

## Обрезка окна на соседних ключах

В окне до 11 слов с квотой 160 ключей на категорию ищем слева и справа
ближайший ключ, категории которого не пересекаются с категориями центрального
ключа. Перекрывающиеся ключевые фразы не разрезаем. При нечётном числе слов
между ключами среднее слово в варианте `halfway` достаётся правому окну.

- `before` оставляет все слова до соседнего ключа.
- `halfway` делит промежуток пополам.
- `after` убирает весь промежуток со стороны соседнего ключа.

```bash
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
PYTHONPATH=src uv run python -m subcategory_extraction.snippet_logistic_regression.train --matrix-dir out/snippet-stops --pair 11 160 --stops
for stop in before halfway after; do
  SNIPPET_LOGISTIC_ARTIFACT="out/snippet-stops/11x160-$stop.json.gz" uv run python \
    src/subcategory_extraction/benchmarks/improved_dataset/run.py --offline \
    --methods snippet_logistic_regression --report "out/snippet-stops/$stop.json"
done
```


На 4 966 строках pooled micro-F1 составил **0.9183**. Внешние фолды
содержали 1 305, 898, 904, 919 и 940 строк, micro-F1 по порядку
0.8683, 0.9561, 0.9334, 0.9504 и 0.8921. Косинусный порог 0.85
дал 2 913 групп, крупнейшая содержит 471 строку. У самой редкой
комбинации меток три строки. Все фолды содержали положительные

обучены на fit, пороги выбраны на отдельном групповом tune.
JSON фиксирует хеши, назначения фолдов и предсказание каждой строки.

### Ручной словарь

- `dictionary/guide-v1.json` — 141 вручную составленный якорь по справочнику.
- `dictionary/listings-v2.json` — те же якоря и 76 новых из открытого train.
- `dictionary/listing-evidence.tsv` — формы из объявлений с номерами строк
  исходного JSONL, фрагментами и пометками контекстных слов.
- `dictionary/legacy-review.tsv` — решения по всем 367 прежним кандидатам
  и их исходные ранги. Ранг отражает статистическую связь с меткой.

Фразы записаны строчными буквами с заменой ё на е. Для применения
ручного словаря предлагается точное совпадение последовательности
целых токенов внутри одного пункта или предложения. Часть словоформ
перечислена явно. Якорь обозначает тему. Отрицания и упоминания
смежных услуг нужно интерпретировать в контексте. В групповом эксперименте ручной словарь поддерживает фразы длиннее
двух токенов. Оценка расширенной версии разведочная, поскольку при
составлении использовались строки из этих фолдов.

Для каждого словаря обучена регрессия на объединённых признаках
объявлений. Затем те же веса применены двумя способами, с отдельным
подбором порогов на tune. При максимуме учитываются все окна для
каждой категории. Сохранённые назначения фолдов сверены с хешем
датасета. Вариант со старым словарём и объединением воспроизвёл
исходные предсказания и пороги.

Старый словарь с максимумом дал на 444 пропуска меньше и на 140
ложных срабатываний больше. Основное снижение пропусков пришлось
на штукатурку (255 → 73) и покраску с обоями (401 → 184).
Сравнение измеряет способ оценки с общими весами. Артефакт
для нового способа оценки потребуется обучить отдельно.

## Групповой holdout и проверки контекста

Для группового эксперимента используем зафиксированные исходные файлы
организаторов. Подготовка сохраняет номера исходных строк, исключает группы,
связанные с public test, и создаёт очередь для слепой ручной разметки.

```bash
PYTHONPATH=src uv run python -m dataset_annotation.prepare_group_holdout out/organizer-group-holdout
PYTHONPATH=src uv run python -m subcategory_extraction.snippet_logistic_regression.compare_windows \
  out/organizer-group-holdout out/organizer-group-holdout/tune-windows.json
```

В локальном прогоне 7 128 строк использованы для обучения и 1 331 для
подбора порогов. На tune словарь дал 0.7027 micro-F1, регрессия с максимумом
по всем окнам — 0.9547, максимум по своим окнам — 0.9521. Holdout содержит
495 уникальных описаний для ручной проверки. Финальной метрики пока нет.

Отдельная проверка регрессии с максимумом по всем окнам на специально
составленных текстах дала 12 верных выдач из 15 положительных и 32 ложные
выдачи из 33 отрицательных. Прямое «не выполняем» не изменило решение
ни в одной из пяти пар. Это диагностика поведения, а не оценка частоты
ошибок в потоке. Поставляемый артефакт `artifacts/model.json.gz` относится
к исходному варианту с объединением признаков. Для него зафиксированный
снимок и настройки обучения указаны в `artifacts/metadata.json`.
