# Классификация услуг с фильтром запретов

Для подключения задайте `"subcategory_extraction": "lexical.order_format_joint"`
в корневом `config.json`.

1. Удаляем поисковые блоки и теги с помощью `clean_description`.
2. Исходный snippet-логрег предлагает категории. У кандидатов 102, 103 и 105
   проверяем наличие соответствующих формулировок вне списка материалов.
   Для прямой облицовки плиткой, пропущенной из-за словоформы, повторно
   даём логрегу каноническое выражение «укладка плитки». Весов не меняем.
3. Фильтр `veto` снимает категории по общему или адресному запрету.
   В частности, может снять категорию, которую удалось восстановить
   на предыдущем шаге. Явно разрешённая услуга сохраняется при общем отказе.

Проверка на 30 ранее разобранных строках дала 25 совпадений с ручной
разметкой и 5 спорных случаев. До правок было 17 совпадений, 8 ошибок и
5 спорных случаев. Эти строки использовались для разработки.

На 18 других строках официального test, выбранных до правок, точных
совпадений с ручной сверкой стало 13 вместо 7. Осталось 3 ошибки и 2
спорных случая. Разбор и полные прогнозы находятся в
`out/order-format/joint-review.md` и `out/order-format/joint-results.json`.
Проверка упоминаний ещё может принять электрику в проекте за монтаж.
Для сантехники такую проверку в этом варианте не вводили.

## Сравнение источников обучения на одном сплите дедупа

Обучены два варианта логрега. В одном источником служит локальный
`igh_deduped_no_conflict.jsonl`, во втором — разметка Decision 1 для
Яндекса и Юлы. Модели используют одинаковую схему признаков и калибровки.
Словари и пороги строятся для каждого источника отдельно на его fit и tune.
Нормализованные исходные и очищенные описания сгруппированы вместе.
Группы общего теста отсутствуют в fit и tune обоих вариантов. Группы
официального и ручного тестов также отложены от обучения.

Для повторения нужны зафиксированный сплит и те же файлы источников.
Команда проверяет их отпечатки перед обучением.

```bash
PYTHONPATH=src uv run python -m subcategory_extraction.lexical.order_format_joint.train \
  out/order-format/dedup-source-comparison-split.json \
  docs/fih/igh_deduped_no_conflict.jsonl \
  docs/provider_collections/yandex-1492-decision-1.jsonl \
  docs/provider_collections/youla-1469-decision-1.jsonl \
  out/order-format-reproduction/results.json \
  --artifact-dir out/order-format-reproduction/artifacts
```

Для запуска любого варианта с `lexical.order_format_joint` укажите
абсолютный путь до `artifacts/dedup.json.gz` или
`artifacts/yandex_youla.json.gz` в `SNIPPET_LOGISTIC_ARTIFACT`.
Результаты в JSON содержат метрики по исходным меткам дедупа, промежуточные
кандидаты и решения фильтра на 699 общих тестовых объявлениях. Размеченного
теста формата заказа достаточного размера в этом сплите нет.

## Абляция проверки кандидатов

`ablation.py` переобучает логрег внутри каждого из пяти внешних групповых
фолдов. Словарь и веса обучаются на fit, пороги подбираются на внутреннем
tune. Перед прогоном отложены 849 строк и исключены 560 строк из ранее
разобранных групп. Выбор варианта сделан по 2 712 прогнозам вне
обучающих фолдов и зафиксирован до прогона отложенной части. Прежние 699
строк используются как регрессия. В мягком варианте проверка упоминаний
может снять кандидата только в пределах 0,25 логита выше порога. Значение
зафиксировано до измерений. Все варианты получают одинаковые оценки
логрега и используют один неизменный veto.

```bash
PYTHONPATH=src OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 uv run python -m \
  subcategory_extraction.lexical.order_format_joint.ablation \
  out/order-format/veto-ablation-clean-split.json \
  out/order-format/dedup-source-comparison-split.json \
  docs/fih/igh_deduped_no_conflict.jsonl \
  out/order-format/veto-ablation-clean-results.json
```

Для воспроизведения нужны сохранённые локальные манифесты сплитов и снимок
дедупа. SHA-256 манифеста и построчные прогнозы записываются в отчёт.

Micro-F1 прямого veto на отложенной части — 0,9617, текущего joint — 0,9621,
мягкой проверки — 0,9625. Оценка после выбора варианта относится к
отложенной части переобученных моделей из прежнего пула. На ней прямой
veto изменил шесть объявлений. Из них в одном отказ от мелких работ
ошибочно перекрыл явно предложенные крупные этапы.

Для модели Яндекс + Юла прямой veto на официальном снимке Avito (208
строк) дал 0,7770 micro-F1 при 0,7774 у чистого логрега. В одном из двух
срабатываний явный запрет частичных работ противоречит исходным меткам
теста. На полном локальном дедупе (4 966 строк) прямой veto дал 0,9226
при 0,9057 у чистого логрега. После исключения 15 строк из групп fit/tune
провайдеров и ещё 633 строк из ранее разобранных групп осталось 4 318
объявлений. На них micro-F1 составил 0,9170 против 0,9143, а фильтр снял
71 ложную и 10 верных меток по исходной разметке дедупа. Эти локальные
замеры дополняют общие сценарии бенчмарка.
