# Как работает remont_mc v0.4

Решение определяет по тексту объявления, какие услуги исполнитель предлагает в микрокатегориях 102–106. Одному объявлению может соответствовать несколько категорий или ни одной. Категорию 101 эта версия не возвращает.

| mcId | Услуга |
| --- | --- |
| 102 | Штукатурные работы |
| 103 | Плиточные работы |
| 104 | Сантехника |
| 105 | Электрика |
| 106 | Поклейка обоев и малярные работы |

Решение сочетает правила и нейросеть RuModernBERT. Правила сначала разбирают текст; их результат передаётся нейросети вместе с объявлением. Затем программа объединяет оценки модели с результатом правил.

## Как обучена модель

За основу взята предобученная языковая модель `deepvk/RuModernBERT-base`. Согласно метаданным поставляемых весов, её дообучали три эпохи на 29 709 примерах. Обучение проходило на GPU, после чего модель экспортировали в ONNX и квантизовали до int8 для запуска на CPU.

По описанию автора, обучающий набор v6 объединяет:

- обучающую часть обработанного дедупа;
- обучающую часть объявлений Юлы и Яндекса;
- синтетические объявления и сочетания нескольких синтетических объявлений.

Метки для обучения получали от модели-учителя DeepSeek-Flash. Синтетические примеры оставляли, когда метки учителя совпадали с категориями, заданными при создании примера. Таким образом, ученик обучался по готовым меткам учителя; сама DeepSeek при работе классификатора не вызывается.

Каждый пример содержит очищенный текст и метки категорий. Перед текстом добавляется результат правил в текстовом виде. Модель учится выдавать отдельную оценку для каждой из пяти категорий: задача многометочная, поэтому одновременно могут быть выбраны несколько услуг.

По документации автора, тестовые и близкие к ним объявления исключались при подготовке обучающих данных. Правила при этом разрабатывались с просмотром теста. Полный состав и команды подготовки описаны в `docs/TRAINING.md` исходного архива решения.

## Как обрабатывается объявление

1. **Очистка.** Программа очищает описание, в том числе от некоторых служебных фрагментов и SEO-хвостов.
2. **Правила.** Словари и правила ищут упоминания услуг и учитывают контекст, например отрицания, работу другого мастера и прошлые услуги.
3. **Подсказка модели.** Результат правил добавляется обычной строкой перед очищенным описанием. Например:

   ```text
   правила: штукатурка нет; плитка да; сантехника нет; электрика нет; обои/покраска нет
   Кладу плитку, сантехнику делает ваш мастер
   ```

4. **Оценки нейросети.** Токенизатор преобразует объединённый текст в токены, а RuModernBERT выдаёт пять оценок — по одной на категорию. Модель обучалась на входах с таким же текстовым префиксом. Максимальная длина входа — 1 536 токенов, включая подсказку; более длинный вход обрезается.
5. **Объединение.** Программа применяет приоритетные правила и пороги, затем формирует список `mcId`.

## Как выбираются категории

Для обычного случая по умолчанию используются два порога:

- если оценка модели для категории **не ниже 0,5**, категория добавляется;
- если категорию уже нашли правила, достаточно оценки модели **не ниже 0,2**.

Например, если правила нашли плитку, а модель оценила её в 0,35, категория 103 останется в результате. Более низкий порог позволяет сохранить часть услуг, которые модель сама не выбрала бы при пороге 0,5. Он может повысить полноту, но также сохранить ошибку правил. Это настройки решения: без независимого сравнения нельзя заключить, что они улучшают качество на новых данных. Оценки модели не следует автоматически считать точно откалиброванными вероятностями.

Два вида правил имеют приоритет над оценкой модели:

- если правило определило объявление как не предлагающее ремонтную услугу, например вакансию или продажу, возвращается пустой список;
- если правило распознало, что конкретную услугу можно заказать отдельно при общем ограничении «только под ключ», эта категория сохраняется.

Эти приоритеты реализованы явными проверками в коде после получения оценок модели.

## Что возвращается

Внутренняя функция возвращает список идентификаторов `mcId`, названия категорий и текст `explanation`. Объяснение формируется программой на основе сработавших правил и найденных фрагментов; нейросеть не генерирует его как свободный текст.

Для примера «Кладу плитку, сантехнику делает ваш мастер» классификатор возвращает `103`: плиточные работы предложены исполнителем, а сантехника отнесена к другому мастеру. При интеграции для классификации можно использовать только список идентификаторов; объяснение полезно при ручной проверке.

## Что показала проверка

Поставляемая модель и правила были запущены на 262 описаниях с оценкой по `docs/responce.csv`: micro-F1 **0,9806**, precision **0,9851**, recall **0,9761**; полный набор категорий совпал в 249 случаях из 262. Правила разрабатывались с просмотром этого теста, поэтому результат является регрессионным и не показывает независимое качество на новых объявлениях.

При проверке точных нормализованных текстов совпадений между тестом и проверенными исходными обучающими наборами не обнаружено. Близкие совпадения повторно не пересчитывались. Готовые веса обучены на смеси источников, указанной выше; в этой проверке модель не переобучалась.
