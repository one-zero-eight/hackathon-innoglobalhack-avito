# Evidence → Jev: извлечение цитат перед классификацией

Сервис: `subcategory_extraction`  
Модуль: `evidence_jev`  
Дата: 2026-11-14

## Зафиксированный метод

Один заранее заданный вариант, без validation/holdout, подбора по официальному
тесту и обещаний целевой F1. `StructuredLLMClient` запрашивает сильную генеративную
модель (по умолчанию `gpt-6.1-terra`) и извлекает перечень текущих услуг:
`{"evidence": [{"mcId": 104, "quote": "..."}]}`. Разрешены все категории
`MICROCATEGORIES`, кроме исходной. Передаётся полный `description`, исходный
`mcId`, таблица eligible категорий с названиями и существующими `CATEGORY_EXAMPLES`.
Промпт хранится в `evidence_jev/prompts/extract.md`.

Все поля JSON обязательны; вложенные объекты и корень имеют Pydantic
`ConfigDict(extra="forbid", strict=True)`. `mcId` — настоящий integer из общей
таблицы (не bool), не исходная категория. Каждая цитата непустая, содержит не
только пробелы и является **точной непрерывной подстрокой** полного исходного
текста. Реализация строже допустимой нормализации пробелов: даже пробелы и
переводы строк должны совпасть. Перефразировка, исправление опечаток и склейка
фрагментов отвергаются. Пустой `evidence` допустим только как реальный валидный
ответ модели, а не результат перехвата ошибки.

Динамическая Pydantic-схема связывает проверки категории и цитат с конкретным
входом; общий клиент выполняет их до записи настоящего ответа в API-кэш.
Ошибка сети, JSON, схемы или цитат прерывает вызов: повторных запросов,
молчаливого `[]`, запасной модели и искусственных результатов нет.

Затем существующий **нативный `JevClient`** одним вызовом оценивает все eligible
категории. Его state содержит неизменённый полный `description` и фактически
извлечённые цитаты как `auxiliary_evidence`. Используются существующие guided
rules и `CATEGORY_EXAMPLES`; инструкции явно запрещают считать цитаты полным
перечнем услуг. Это не hard gate: даже при пустом evidence Jev видит весь текст
и может выбрать любую допустимую категорию. Выход — настоящие вероятности Jev;
`run()` возвращает категории с **p ≥ 0.5**. Исходная категория исключена.

## Запуск и вход

Модуль создаётся без аргументов, наследует `BasePipeline` и поддерживает
`run(PipelineInput) -> list[int]`. Для выбора в `config.json`:

```json
{
  "subcategory_extraction": "evidence_jev",
  "draft_generation": "sample_llm"
}
```

Пример входа (иллюстрация контракта, не строка официального теста):

```json
{
  "description": "Ремонт квартир. Монтаж сантехники и укладка плитки.",
  "mcId": 101
}
```

Общее сравнение, из корня репозитория:

```bash
uv run python src/subcategory_extraction/benchmarks/classifier_methods/run.py --methods evidence_jev jev_arbiter
```

## Окружение и воспроизводимость

- `BESTAPI_API_KEY` — обязательный секрет при отсутствии закэшированного ответа.
- `STRUCTURED_LLM_MODEL` — по умолчанию `gpt-6.1-terra`;
  `STRUCTURED_LLM_ENDPOINT`, `STRUCTURED_LLM_TIMEOUT`,
  `STRUCTURED_LLM_CACHE_DIR` — настройки общего клиента. По умолчанию
  OpenAI-совместимый BestAPI chat/completions, timeout 90 секунд,
  кэш `out/structured-llm-cache`. Общий клиент использует strict JSON Schema,
  `max_completion_tokens=4096`; temperature отдельно не задаётся.
- `JEV_MODEL` — по умолчанию `jev-1.13.0`; `JEV_ENDPOINT`, `JEV_TIMEOUT`,
  `JEV_CACHE_DIR` — настройки существующего нативного клиента. По умолчанию
  BestAPI SystemOne, timeout 60 секунд, кэш `out/jev-cache`.
- Порог этого метода фиксирован 0.5 и не берётся из `JEV_THRESHOLD`.
  Guided-промпт читается из штатного `DEFAULT_PROMPT_PATH`, а не
  `JEV_PROMPT_PATH`; промпт извлечения также фиксирован файлом метода.
- Импорт не создаёт сетевых запросов. На объявление — один вызов извлечения
  и один нативный вызов Jev (либо соответствующие настоящие ответы из кэша).
  Оба кэша учитывают endpoint и полный payload; протокол кэширования не дублируется.
- Для provenance доступны `.extractor`, `.client`, их `.model_id`, endpoint,
  `last_cache_hit`, `last_usage`, а у extractor также `last_model`;
  `.threshold`, `.extraction_prompt`, `.decision_prompt`, `.last_evidence`.
  Фактические ID и расходы берутся из клиентов/отчёта, не из предположения
  о том, какой alias настроен в окружении.

## Оценка и ограничения

Официальный тест: все 208 строк `public-test-dataset.parquet`, включая
противоречивые дубликаты. Метрика — общий `run.calculate_metrics`: sklearn
micro-F1 и `60 * F1`. Метод не обучается и не использует метки теста в промпте.
Настройки должны оставаться фиксированными до единого запуска сравнения.

Общий запуск был выполнен, но BestAPI отклонил предоставленный ключ с HTTP 401.
Отдельный запрос списка моделей подтвердил `invalid api key`; F1 этого метода
не измерен. Ошибка записана без подстановки пустых предсказаний или нулевого F1.
Фактический статус и результаты остальных методов — [общий отчёт](../benchmarks/classifier_methods/README.md).

Дословная цитата доказывает наличие фрагмента, но сама по себе не гарантирует
правильную интерпретацию услуги, отрицания или текущего предложения. Извлечение
может пропустить полезные фрагменты, а Jev — ошибиться независимо от них.
Полный текст не обрезается; ограничения контекста и лимит ответа API могут дать
явную ошибку. Два последовательных модельных этапа повышают задержку и стоимость.
